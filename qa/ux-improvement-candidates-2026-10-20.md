## 화면별 관찰

### 홈
- 게스트에게도 "첫 출조 추가하기"와 "현장에서 기록하기"가 그대로 보이고, 누르면 말없이 로그인 화면으로 넘어간다. 왜 로그인해야 하는지 설명이 없다.
- 히어로 문구 "첫 출조를 기다리는 중 · 어디로 떠날지 기록해보세요"는 좋지만, 앱이 뭘 해 주는지(출조 계획 → 현장 기록 → 도감·배지)는 어디에도 없다. 온보딩 관련 코드가 없다(`onboarding`, `firstLaunch` 검색 결과 0).
- 상단 "FIELD LOG 000"은 출조 수다. 숫자 의미가 설명되지 않는다.

### 일지
- 빈 상태인데 "새 출조 +"(헤더), "새 출조 추가"(리스트 첫 행), "첫 출조 기록하기"(빈 상태 버튼) 세 개가 한 화면에 있다. 빈 상태일 때는 하나로 줄이는 편이 낫다.
- "TOTAL 0 | 예정 0 · 완료 0 · 취소 0"과 전체/예정/완료/취소 탭은 데이터가 없을 때 노이즈다.

### 지도
- 빈 상태 카드 "아직 지도에 표시할 기록이 없습니다"가 수도권 전체를 가린다. 상단 한 줄 배너나 첫 탭 시 사라지는 힌트로 줄일 수 있다.
- 바다를 누르면 시트가 열리지만 게스트에게는 "불러오기 실패 · 눌러서 다시 확인"이 뜬다. 훅은 "로그인 후 해양 정보를 확인할 수 있습니다"를 던지는데 시트가 이를 버리고 일반 문구만 보여준다(`components/map/PlaceInfoSheet.tsx` 200행). 메시지를 그대로 노출하고 로그인 버튼을 붙이면 된다.
- 즐겨찾기 별, "이 장소로 출조 계획" 버튼도 게스트에게 보인다. 눌러야 로그인 요구를 알게 된다.
- 필터 칩의 "0" 배지 네 개는 기록이 없을 때 숨기는 편이 깔끔하다.

### 수집(도감)
- 잠긴 어종 카드는 "미확인 어종 / DISCOVERY REQUIRED"와 그룹명만 보여준다. 제철·미끼·주요 지역 같은 힌트를 잠금 상태에서도 보여주면 "다음에 뭘 노릴지"가 생긴다. 발견한 어종 카드에는 이미 같은 정보("금지체장 35cm · 미끼 섀드웜")가 있으니 데이터는 준비돼 있다.
- 학명 줄이 "(TEMMINCK & SCHLEGEL, 184…"로 잘린다. 명명자·연도는 두 번째 줄로 내리거나 상세에서만 보여주는 편이 낫다.
- "01 ALL SPECIMENS", "FIELD 60 · V1" 같은 영문 장식은 분위기용이지만 한국어 사용자에게 정보가 없다.
- 참고: Debug 빌드의 게스트는 `__DEV__` 미리보기로 2/60이 발견된 것처럼 보인다. 출시 빌드에는 나오지 않는다.

### 프로필
- 게스트인데 "바다형제 @baited_brother LOG OWNER 019"라는 가짜 신원이 보이고, 로그인 버튼은 리스트 맨 아래에 있다. 게스트일 때는 상단에 "로그인하면 기록이 한 계정에 모입니다" 카드가 와야 한다.
- "LOG OWNER 019"는 모든 사용자에게 같은 하드코딩 문자열이다(`app/(tabs)/profile.tsx` 89행). 실제 가입 순번을 쓰거나 지워야 한다.
- 통계 "수집 어종 0 · 획득 배지 0 · 조과 카드 0"은 게스트에게 의미가 없다.

### 로그인·가입·비밀번호 재설정
- 세 화면 모두 디자인이 일관되고 문구가 좋다. "닫기"로 게스트 복귀가 가능한 점도 좋다.
- Google 버튼을 누르면 iOS 시스템 시트에 "'app'이(가) 'supabase.co'을(를) 사용하여 로그인하려고 합니다"가 뜬다. 'app'은 CFBundleName이 PRODUCT_NAME(app)이라서다. `ios/` 프로젝트가 커밋된 bare 워크플로라 `app.json`의 infoPlist만으로는 반영되지 않아 `ios/app/Info.plist`의 CFBundleName도 직접 앱 이름으로 바꿨다. 재빌드 후 시트에 '낚시당한 녀석들'이 표시되는 것을 확인했다. 'supabase.co' 부분은 Supabase 커스텀 도메인을 써야 바뀐다.
- Metro 경고: "WebCrypto API is not supported. Code challenge method will default to use plain instead of sha256." React Native에는 `crypto.subtle`이 없어 PKCE 챌린지가 plain으로 떨어진다. `expo-crypto`를 추가하고 앱 진입 시 `crypto.subtle.digest`를 폴리필해야 sha256이 된다. 동작에는 지장이 없지만 PKCE의 보호 효과가 줄어든다.

### 로그인 이후(코드로 확인)
- 기록 완료 화면 CTA는 "도감 보기 / 카드 보기 / 공유 카드 만들기 / 한 마리 더 기록하기 / 홈으로" 다섯 개다. 많기도 하고, 정작 "이 조과를 오늘 출조에 연결" 같은 다음 행동이 없다. 출조가 진행 중이면 그 출조로 돌아가는 한 개의 주 CTA가 낫다.
- 출조 폼은 장소명(placeholder "예: 대천항 방파제")과 메모만 있다. 지도 시트의 "이 장소로 출조 계획"에서 들어오면 장소가 채워지지만, 홈·일지에서 들어오면 빈 폼이라 지도 선택으로 유도하는 안내가 필요하다.

## 추천 순서

1. **온보딩 3장 + 게스트 상태 정리(1·2번)**: 첫 실행에서 "출조 계획 → 현장 기록 → 도감·배지"를 세 장으로 보여주고, 게스트 화면마다 왜 로그인이 필요한지 한 줄과 버튼을 둔다. 가짜 핸들과 "불러오기 실패"는 이때 같이 정리한다.
2. **도감 힌트 노출(3번)**: 잠긴 카드에 제철·미끼·그룹을 보여준다. 데이터가 이미 있어 UI만 바꾸면 된다.
3. **빈 상태 정리(4·5번)**: 지도 카드 축소, 일지 CTA 하나로 통합, 0 배지 숨김.
4. **완료 화면 다음 행동(6번)**과 영문 라벨(7번)은 그 다음.

PKCE sha256 폴리필은 UX는 아니지만 다음 빌드 전에 넣는 것을 권한다.
