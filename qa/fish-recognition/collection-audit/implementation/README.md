# 동의 기반 판별 개선 자료 수집 — 2026-09-10

## 구현과 배포
- 사진 판별 후 사진별로 설명을 펼쳐 읽고 ‘동의하고 제공’을 선택해야 업로드한다. 최초 표시·안내 열기·제공 거절은 업로드하지 않는다.
- 판별 성공/재촬영 안내/요청 실패의 사진, 후보 순서·점수·이유, 모델/판별 버전, 처리 시간과 상태를 보존한다. 구버전 응답의 모델 정보는 추정하지 않고 null로 둔다.
- 조과 저장과 독립적으로 제공할 수 있고, 이후 조과 저장/어종 수정은 user_id + client_request_id로 연결한다. 조과 삭제는 연결된 자료를 즉시 검토 대상에서 제외하고 다음 정리 작업에서 삭제한다.
- 사용자 어종은 user_selected/unreviewed, 앱이 보낸 예측은 client_reported다. 전문 검수 정답이나 신뢰할 수 있는 서버 감사 로그로 취급하지 않는다. 자동 학습은 구현하지 않았다.
- 설정/프로필 → 사진 제공 관리에서 개별 또는 전체 철회·삭제한다. 원래 조과와 그 사진은 별도로 유지한다.
- 기존 비공개 user-uploads 아래 별도 경로를 사용한다. 기존 계정 삭제의 사용자 폴더 정리와 DB cascade가 적용된다.
- DB 열람 만료 89일, 매시 13분 정리(최대 1,000건/호출). 최대 90일 안내에 여유를 뒀다. 운영 중 예약 작업 실패/적체는 점검해야 한다.
- 운영 DB migration 2개 적용, recognition-contributions v4, identify-fish v32 배포. identify-fish 변경은 결과에 모델/버전 추가이며 운영 실험 플래그는 기존 기본값 false다.
- 개발 전용 identify-fish-qa-evidence v4는 제한된 QA 계정에만 열려 있다. 출시 앱은 항상 identify-fish를 사용한다.

## 검사 결과
- Node 검사 11개: 입력/동의/권한/만료 정리 자격과 기존 판별 회귀.
- Jest 10개: 판별 결과 보존, 미완료 큐, 명시적 동의만 요청을 보내는 UI.
- 앱 범위 TypeScript, 새 Edge 함수 Deno 타입 검사, git diff --check 통과.
- DB 트랜잭션 검사: 중복 예약, 조과 저장·어종 수정·삭제 연결. 검사 후 rollback.
- 실제 QA 계정 2개: 동의 없는 제출 거부, 중복 제출 동일 결과, 사진 저장, 타 계정 조회/삭제 차단, 직접 테이블 접근 차단, 철회 원본 삭제, 만료 원본 삭제. live-checks.json 참고.
- iPhone 17 iOS 26.3: 실제 공개 사진 판별 → 제공 거절(서버 0건) → 동의(사진+후보 3개+버전 저장) → 관리 1장 표시 → 철회 → DB와 Storage 0건 확인.
- 전체 화면 record에서 루트 팝업이 가려지는 문제를 피하도록 동의를 카드 안에서 펼친다. 관리 화면은 루트에 초기 headerShown:false를 등록해 동적 헤더 변경 오류를 수정했다.
- 삭제 직후 동일 다운로드 URL은 캐시를 반환할 수 있어 원본 확인에는 새 요청 URL을 사용했다. 신규 개선 자료는 cacheControl:0으로 업로드한다.
- 모든 QA 계정과 미완료 사진을 보존했다. 이번 검사에서 만든 서버 제공 자료만 철회했다. iPhone 17 Pro/다른 프로젝트 서버는 건드리지 않았다.
