# 광고 전 AI 판별 1차 수정 검증

> 후속 데이터 검수에서 reviewed-21의 표본 라벨 불일치가 발견되어 황돔 사례를 격리했습니다. 아래 8장 표는 당시 입력 기준의 역사적 기록입니다. 해당 1장을 제외하면 당시 Top-3는 2/7 → 5/7, Top-1은 2/7 → 3/7이며, 어느 수치도 앱 전체 정확도를 의미하지 않습니다. 새 비교에는 이 사진을 사용하지 않습니다.

## 변경 및 배포

- 운영 identify-fish v29 → v30. 인증과 일일 판별 횟수 제한은 유지.
- 같은 어종군이라는 이유로 기존 2·3순위 후보를 다른 군으로 교체하던 로직 제거. 인접 어종군은 최초 비교 목록에 계속 포함.
- 종명 선택 전에 보이는 특징을 기록하도록 변경. 촬영 방향과 해부학적 좌우 구분, 겹친 개체 분리, 보이지 않는 특징을 부재로 단정하지 않도록 지침 보완.
- 별도 QA 함수에서 검증 후 운영 배포. 임시 QA 함수는 검증 종료 후 410 응답으로 닫음.

## 검증 범위와 남은 문제

- 회귀 테스트: 후보 교체 오류 재현 시 실패 → 수정 후 통과. 새 핸들러 테스트 2개와 기존 품질 검사·앱 훅 테스트 12개 통과.
- 넙치 사진은 여전히 오인식한다. 강도다리 사진은 두 버전 모두 품질 검사에서 거절한다.
- 조피볼락은 수정판에서 품질 검사를 통과했지만, 품질 검사 지침은 바꾸지 않았다. 이 차이를 이번 수정의 확정적 효과로 해석하면 안 된다.
- 참돔은 비교 검사에서 후보에 남았고, 운영 배포 후 PNG 재검사에서는 1순위로 나왔다. 후보 순위가 변동하므로 사진별 반복 측정과 실제 초보자 촬영 사진 평가가 필요하다.
- 소수 표본과 프롬프트 개발에 사용한 사진이 포함된 회귀 검사다. 앱 전체 정확도 75% 또는 정확도 두 배라는 광고 근거로 사용할 수 없다.
- 기존 평가 기준(어종당 5장, 비어류·저화질 각 30장, Top-3 90%·거절 95%)을 충족한 결과가 아니다.
- 운영 배포 후 넙치·참돔 요청 2건 모두 정상 응답(각 22.6초·19.6초). 넙치는 오인식 유지, 참돔은 1순위. 운영 v30 소스가 테스트한 로컬 소스와 일치하고 JWT 검증이 켜져 있음을 확인.
- 이번 검증은 API와 관련 자동 테스트를 대상으로 했다. 앱 전체 빌드 성공을 의미하지 않는다.

## 재현 자료

- `pre-ad-regression-manifest.json`: 고정 입력 경로와 원본 해시
- `pre-ad-baseline.json`, `pre-ad-candidate.json`: 전체 응답과 소요 시간
- `candidate-preservation-diagnostic.json`: 후보 보존만 수정한 두 사례
- `visual-evidence-diagnostic.json`: 관찰 지침까지 수정한 두 사례
- `pre-ad-production-smoke.json`: 운영 배포 후 응답

```sh
node --test scripts/identify-fish.test.mjs
npm run test:ci -- --runTestsByPath src/lib/__tests__/fishQualityGate.test.ts src/hooks/__tests__/useFishRecognition.test.ts
```

실사진 재평가는 유효한 테스트 사용자 JWT를 환경변수 AI_TEST_USER_JWT로 주입하고, QA_MANIFEST_PATH=qa/fish-recognition/pre-ad-regression-manifest.json 및 QA_RESULT_PATH를 지정해 기존 qa:fish-recognition 스크립트로 실행한다. QA_FUNCTION_NAME은 기본 identify-fish이며, 별도 배포한 테스트 함수를 지정할 수도 있다. 인증정보는 결과 파일에 저장하지 않는다.
